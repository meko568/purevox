PureVox docs

CLI and desktop app — install, flags, and usage. Everything runs locally, nothing uploads anywhere.

Install the CLI

Needs Demucs, ffmpeg/ffprobe, and Python (for pipx). Install, then put purevox on your PATH.

sudo apt install python3-pip ffmpeg
pip install --user pipx
pipx ensurepath
pipx install demucs

chmod +x purevox
sudo mv purevox /usr/local/bin/

Verify:

purevox --help

Use Homebrew for ffmpeg and pipx, then install Demucs and add purevox to your PATH.

brew install ffmpeg pipx
pipx ensurepath
pipx install demucs

chmod +x purevox
sudo mv purevox /usr/local/bin/

Verify:

purevox --help
Apple Silicon and Intel both work — Demucs runs on CPU if there's no CUDA GPU, just slower.

purevox is a bash script, so native cmd/PowerShell can't run it directly. Use WSL (recommended) or Git Bash.

wsl --install
# reboot, open the new Ubuntu shell, then:
sudo apt update && sudo apt install python3-pip ffmpeg
pip install --user pipx
pipx ensurepath
pipx install demucs

chmod +x purevox
sudo mv purevox /usr/local/bin/
Inside WSL your Windows drives are mounted at /mnt/c/..., so you can point -i/-o straight at files in your normal Windows folders.

Install the desktop app

Download directly, no clone needed:

  • PureVox_0.1.1_amd64.AppImage — works on most distros
  • PureVox_0.1.1_amd64.deb — Debian/Ubuntu
  • PureVox-0.1.1-1.x86_64.rpm — Fedora/RHEL

AppImage: make it executable, then run it.

chmod +x PureVox_0.1.1_amd64.AppImage
./PureVox_0.1.1_amd64.AppImage
If you've also installed the CLI, running purevox in a terminal opens the CLI, not the app — the desktop build currently ships a binary with the same name. Launch the desktop app from your applications menu, or open it directly with /usr/bin/purevox. A future release renames the desktop binary to avoid this clash.

Or build from source instead:

sudo apt install libwebkit2gtk-4.1-dev libglib2.0-dev libgtk-3-dev \
  libayatana-appindicator3-dev librsvg2-dev patchelf build-essential \
  curl wget file libssl-dev

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
cargo install tauri-cli --version "^2.0.0"

git clone https://github.com/meko568/purevox.git
cd purevox/desktop
cargo tauri build

The built .AppImage/.deb lands in desktop/src-tauri/target/release/bundle/.

Basic CLI usage

purevox -i in.mp4 -o out.mp4

Extension on -o is optional — defaults to .mp4 (or the input's audio extension if the input is audio-only).

Batch — explicit file pairs

purevox -i in1.mp4 in2.mp4 in3.mp4 -o out1.mp4 out2.mp4 out3.mp4

Batch — folder of outputs

purevox -i in1.mp4 in2.mp4 -o clean_folder/

Outputs auto-named from each input's basename, saved into the folder.

Whole folder in, whole folder out

purevox --dir episodes/ -o clean/

Processes every video file (mp4/mkv/mov/avi/webm) inside the folder.

Search current folder

purevox -s attackS1 -o clean/

Interactive checklist of matching files in the current folder — all selected by default, Space toggles, Enter runs, q cancels.

Episode-number shorthand

purevox -e attackS1E 1,2,4 -o clean/
purevox -e attackS1E 1,2,4 -eo cleanS1E 1,2,4

-e builds input names, -eo builds output names — independent, use either or both. Ranges like 1-4 work too.

Resuming interrupted jobs

purevox -r
purevox -r 0
purevox -r 0 2 5
purevox -r -i in1.mp4 in2.mp4 -o out1.mp4 out2.mp4
purevox -r --dir episodes/ -o clean/

No id given: resumes the only pending job, or shows a checklist if there are several. Chunked jobs resume per-chunk — only unfinished chunks get reprocessed.

Listing / deleting jobs

purevox --jobs
purevox --delete
purevox --delete 0 2
purevox --delete all

Dry run & partial batches

purevox --dry-run -i in1.mp4 in2.mp4 -o out1.mp4 out2.mp4
purevox -q 3 -i in1.mp4 in2.mp4 in3.mp4 in4.mp4 -o clean/

--dry-run shows the plan and touches nothing. -q N registers every job but only runs the first N now; the rest stay pending for purevox -r.

Audio-only output

purevox -i in.mp4 -o clean.mp3

If -o ends in an audio extension (mp3/wav/m4a/flac/aac/ogg/wma), PureVox skips the video remux and saves the isolated vocal track directly — even when the input is a video.

Forcing chunk size

purevox -c 12 -i in.mp4 -o out.mp4

Overrides the automatic chunk length (minutes). Warns and asks for confirmation first if the value looks unsafe for your detected RAM/VRAM.

All flags

ShortLongDescription
-h--helpShow usage and exit
-j--jobsList every pending/interrupted job — id, input, output, progress, model
-r--resumeResume pending/interrupted job(s), optionally by id(s)
-i--inputInput file(s)
-o--outputOutput file(s) or folder
-d--dirWhole-folder input mode
-s--searchSearch current folder for matching filenames (interactive pick)
-e--episodesBuild INPUT names from a prefix + episode numbers/ranges
-eo--episodes-outBuild OUTPUT names from a prefix + episode numbers/ranges
-n--dry-runShow the plan, touch nothing
-q--run-limitRegister all jobs, only actually run N of them now
-x--deleteDelete pending job(s), by id or interactively, or all
-c--chunkForce a chunk size in minutes instead of automatic

How the model/chunk size is picked

On every run purevox detects RAM (free -g) and GPU VRAM (nvidia-smi, 0 if no NVIDIA GPU) and picks a model + chunk length automatically:

HardwareModelChunking
GPU VRAM ≥ 4GBhtdemucsfull file (60min chunks if forced)
GPU VRAM ≥ 2GBhtdemucs~20min chunks
RAM ≥ 16GB, no usable GPUhtdemucs~30min chunks
RAM ≥ 8GBhtdemucs~15min chunks
RAM ≥ 6GBhdemucs_mmi~8min chunks (chunked)
RAM ≥ 4GBhdemucs_mmi~5min chunks (chunked)
RAM < 4GBhdemucs_mmi~3min chunks (chunked)
Heuristic, not exact science — override with -c/--chunk if it picks wrong for your machine. Chunking exists to keep memory use safe on low-spec hardware, not to speed things up.

Job state & resume

Every job's progress lives in ~/.purevox/jobs/<hash>/ — a state.json plus a stems/ folder of completed audio/chunks. Survives OS temp-file cleanup, so -r keeps working even after a reboot. On success the job folder is deleted automatically.
